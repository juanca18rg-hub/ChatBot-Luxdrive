## 4. Decisiones técnicas

| Decisión                                                                                                                     | Razón                                                                                                                 | Alternativa descartada                                                            |

| En la primera clase se solicito datos del cliente, del vehículo y del servicio antes de crear una cita                       | Permite registrar la solicitud de manera organizada y unirla con el servicio solicitado<br>                           | Ninguna                                                                           |

## 5. Problemas y soluciones

| Problema encontrado                                                                                   | Causa identificada                                                                                     | Solución aplicada                                                                                         | ¿Cómo se verificó?                                                                             |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| En la primera clase hubo dificultad a la hora de crear citas sin conocer la disponibilidad del taller | La creación de la cita no contemplaba una consulta previa de horarios                                  | Se incorporó la consulta de fechas y horarios disponibles antes de confirmar la reserva                   | la API rechazó los datos inválidos y la reserva solo se creó después de la confirmación        |
| En la primera clase faltaba un mecanismo para identificar una cita registrada                         | La reserva no tenía un identificador asociado                                                          | Se generó un código de confirmación después de registrar cada cita                                        | La reserva de prueba recibió un código de error, se consultó y se soluciono                    |
| En la primera clase era necesario organizar la información solicitada al cliente                      | La información requerida para crear una cita no estaba estructurada                                    | Se definieron los datos principales: nombre del cliente, vehículo, servicio requerido y datos de contacto | El chatbot pidió esos datos antes de mostrar el resumen de la cita                             |
| En la sexta clase  al llamar a Groq la API devolvía error en vez de la respuesta esperada             | La API key se copió con un espacio de más y el ID del modelo no estaba habilitado en la cuenta de Groq | Se revisó primero el código HTTP, se volvió a copiar la clave sin espacios y se confirmó el ID del modelo | Se repitió la petición de prueba y la respuesta llegó                                          |
| En la octava clase al pulsar Enviar en Gradio aparecía un error y la conversación no se actualizaba   | La función enviar devolvía menos valores de los declarados <br>                                        | Se corrigió el return para devolver los cinco valores en el mismo orden                                   | Se volvió a enviar un mensaje y la pantalla, el estado y la caja de texto se actualizaron bien |
